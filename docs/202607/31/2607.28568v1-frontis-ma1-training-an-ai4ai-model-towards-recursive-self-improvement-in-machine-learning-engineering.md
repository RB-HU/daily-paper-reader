## 摘要
递归自我改进（RSI）要求AI系统能够改进构建AI的过程（即AI4AI）；机器学习工程（MLE）为此类能力的研究提供了一个具体、可执行的测试平台。我们引入OpenMLE，这是一个用于MLE中RSI研究的开放式全栈系统，涵盖具备执行反馈的可验证任务环境（OpenMLE-Gym）、算子学习（OpenMLE-RL）以及长时域搜索（OpenMLE-Evo）。基于此栈，我们对Frontis-MA1（35B）进行后训练，使其成为MLE的元进化智能体，围绕四个原子程序进化算子（Draft、Improve、Debug、Crossover）对齐后训练和推理：这些算子通过与所有评估基准去重的数据，通过基于执行的SFT和RL进行训练，然后组合成长时域搜索，在单个循环中耦合学习与进化。在MLE-Bench Lite上，每任务预算12小时，单块RTX 4090显存限制12 GB，Frontis-MA1（35B）借助OpenMLE-Evo将Medal Average从基模型的39.39%提升至60.61%，使用OpenMLE-Evo-Max（基准无关的经验先验与异步搜索）达到71.21%，超过GPT-5.5 + Codex，接近GPT-5.6 Sol和2.8T Kimi K3。在留出的NatureBench Lite上，两个组件均可迁移：固定框架，换入已训练模型，Match-SOTA从50%提升至70%；固定模型，换入OpenMLE-Evo，Match-SOTA从20%提升至50%。我们公开模型权重及完整的OpenMLE栈，以促进面向RSI的可执行AI4AI的可复现研究。代码：https://github.com/FrontisAI/OpenRSI

## Abstract
Recursive self-improvement (RSI) requires AI systems that improve the process of building AI (i.e., AI4AI); machine learning engineering (MLE) offers a concrete, executable testbed for studying this capability. We introduce OpenMLE, an open full-stack system for RSI research in MLE, spanning verifiable task environments with execution feedback (OpenMLE-Gym), operator learning (OpenMLE-RL), and long-horizon search (OpenMLE-Evo). On this stack we post-train Frontis-MA1 (35B) as a meta-evolution agent for MLE, aligning post-training and inference around four atomic program-evolution operators (Draft, Improve, Debug, Crossover): the same operators are trained via execution-grounded SFT and RL on data deduplicated against all evaluation benchmarks, then composed into long-horizon search, coupling learning and evolution in a single loop. On MLE-Bench Lite under a 12-hour per-task budget on one RTX 4090 capped at 12 GB VRAM, Frontis-MA1 (35B) improves Medal Average from 39.39% to 60.61% over its base model with OpenMLE-Evo, and reaches 71.21% with OpenMLE-Evo-Max (benchmark-independent experience priors and asynchronous search), exceeding GPT-5.5 + Codex and approaching GPT-5.6 Sol and the 2.8T Kimi K3. On held-out NatureBench Lite, both components transfer: with the framework fixed, swapping in the trained model raises Match-SOTA from 50% to 70%; with the model fixed, swapping in OpenMLE-Evo raises it from 20% to 50%. We release the model weights and the full OpenMLE stack to enable reproducible research on executable AI4AI toward RSI. Code: https://github.com/FrontisAI/OpenRSI

*   **第二层：OpenMLE-ERL (强化可重用进化算子)**
    *   **核心思想**：训练模型掌握四个原子化的程序进化操作（Draft， Improve， Debug， Crossover），而非训练完整的搜索轨迹。
    *   **关键技术细节**：
        *   **执行反馈的监督微调 (SFT)**：使用教师模型在OpenMLE-Gym环境中进行搜索，收集成功的完整方案和高价值的进化轨迹片段，构成训练语料。采用“预算自适应”策略，将更多尝试分配给难以成功的任务。
        *   **执行反馈的强化学习 (RL)**：
            *   **自适应奖励归一化**：为了解决不同任务评分标准不一的问题，基于任务历史分数的动态边界对原始分数进行重映射，使奖励信号更具辨别力。
            *   **熵加权（Entropic Weighting）**：为强化位于得分上尾部的优秀候选方案，使用指数变换放大组内最优解的优势，引导策略向高质量方案集中。
            *   **异步探索**：解耦生成/执行与模型更新的同步等待，允许训练器在任意探索任务完成后立即消费结果，提高训练吞吐量。
            *   **有信息量的状态选择**：在RL训练中选择父程序时，综合考虑父程序质量、其子代程序得分的方差（学习潜力）和访问冷却系数（避免重复探索），使训练更均衡高效。

*   **第三层：OpenMLE-Evo (基于经验的长时域搜索)**
    *   **核心思想**：在推理时，利用训练好的算子，将搜索过程本身变成一个“边测试边学习”的进化过程，通过积累和利用经验来引导后续搜索。
    *   **关键技术细节**：
        *   **结构化经验积累**：为每个评估过的候选方案创建“经验卡片”，标准化记录其谱系、得分、资源消耗、方法家族等信息，并聚合为全局“经验板”。
        *   **经验引导的父代选择**：选择下一轮改进的起点时，不再仅基于最高分，而是基于一个综合效用函数 `U = 质量 + 相对提升 + 方法新颖度`，通过 Softmax 采样，平衡了探索与利用。
        *   **操作触发的记忆合成**：仅在需要改进、交叉或调试时，才为目标父代及其相关节点（祖先、兄弟姐妹）按需调用LLM合成自然语言记忆，避免了无差别的、不断增长的上下文，使提示词更精简、更具信息量。

*   **训练与搜索的增益可以组合**：单一的SFT或RL训练（模型增益）或单一的OpenMLE-Evo搜索（框架增益）都能带来提升，但将两者结合成“元进化”系统，效果远超任何单一部件。Frontis-MA1 + OpenMLE-Evo-Max 的组合达到了与顶尖模型匹敌的水平。
*   **搜索从“盲目采样”转向“经验学习”**：OpenMLE-Evo通过“经验引导的父代选择”和“操作触发的记忆合成”，相比原始AIRA-Evo不仅消耗更少的Token（-41.7%），而且产生了更多有效的改进（+84.3%的单位Token有效更新），证明了结构化的经验积累是提高长时域搜索效率的核心。
*   **实现了解耦与再组合的进化策略**：案例分析表明，模型学会了先用Debug建立不同分支，再用Crossover进行结构重组，最后用Improve迭代优化，这种进化策略持续驱动性能提升，而非简单的随机采样或修补。
*   **具备跨场景的元能力与迁移性**：在NatureBench Lite上的迁移实验表明，经MLE任务训练后的模型和搜索框架，在不涉及Kaggle竞赛的科学任务上同样有效，初步验证了其习得的“改进AI方案”的能力具有一定的普适性。

### 7. 优点

*   **开源全栈系统**：将任务环境、训练、搜索、评估和模型权重作为一个完整的工作流发布，极大地推动了该领域的可复现性和后续研究。
*   **共享算子接口的创新设计**：将训练（SFT/RL）和推理（进化搜索）统一在Draft、Improve等四个原子上，使训练目标直接服务于推理框架，设计精巧且高效。
*   **从“学习生成”到“学习进化”的范式升级**：论文深刻地区分了单纯学习写代码与学习如何改进代码的能力，其“元进化”思想是对AI4AI和RSI领域的重要贡献。
*   **细致的机制探究**：并非仅仅报告最终分数，而是深入分析了搜索效率、上下文长度、重组机制等，为理解“为何有效”提供了宝贵的洞见。
*   **受限且公平的评估预算**：在非常有限（12h/单卡4090）的算力下取得显著成果，体现了方法的高效性，并降低了复现门槛。

### 8. 不足与局限

*   **离完全的RSI仍有距离**：如作者所述，系统目前主要在优化“外部ML作品”，而非改进自身模型架构或改进搜索算法本身，进化对象是“解决方案”，而非“改进器”。
*   **实验场景相对受限**：评估主要集中在Kaggle风格的结构化MLE任务上，尽管有NatureBench的初步迁移实验，但其规模和多样性（仅10个任务）仍有限，对于更开放、复杂的AI研发任务的泛化能力待验证。
*   **父代选择权重为人工设定**：如何综合质量、增益和新颖性的权重是人为预设的，未来需要学习任务自适应的权重，甚至让搜索策略本身也成为进化的对象。
*   **未充分发挥全部经验信息**：经验卡片虽存储了丰富元数据，但当前选择策略仅使用了三个维度，信息利用率有待提高。
*   **奖励信号单一**：训练主要依赖执行结果分数，缺乏对研究方向价值、假设质量、鲁棒性等更高阶目标的评估，可能限制了智能体在更复杂科研任务中的判断力。
