## 摘要
大语言模型智能体经常花费大量挂钟时间等待工具调用结果。工具调用推测可以通过预测和预执行智能体的下一次工具调用来隐藏这一延迟，但前提是预测与智能体最终的工具调用匹配。然而，现有的推测器通常是独立的草案模型或缓存的轨迹，与部署的智能体自身行为一致性较差。我们识别出这一推测器-智能体差距，并表明目标智能体本身就是一个强大的下一次调用推测器。这指向一种更简单的设计：将智能体和推测器统一在同一模型中。在本文中，我们引入了自推测智能体，它是一个单一模型，既在智能体模式下解决任务，又在推测器模式下从部分轨迹中预测下一次工具调用，并完全重用前缀 KV 缓存。为了使这种双模智能体在不降低性能的情况下运行，我们提出了一种联合智能体-推测器强化学习方法，该方法从智能体自身的展开中推导推测目标，并交替进行智能体和推测器更新。在智能搜索问答和会话式工具使用智能任务上，我们的方法将 Qwen3-4B 的平均下一次工具调用 Hit@1 从 44.1 提高到 61.2，将 Qwen3.5-4B 的从 48.9 提高到 66.3，同时保持了智能体任务成功率。

## Abstract
Large language model agents often spend substantial wall-clock time waiting for tool call results. Tool-call speculation can hide this latency by predicting and pre-executing an agent's next tool call if the prediction matches the agent's eventual tool call, but existing speculators are typically separate draft models or cached traces that are poorly aligned with the deployed agent's own behavior. We identify this speculator-agent gap and show that the target agent itself is a strong next-call speculator. This points to a simpler design: unifying the agent and speculator within the same model. In this paper, we introduce the self-speculating agent, a single model that both solves tasks in agent mode and predicts its next tool call from partial trajectories in speculator mode, fully reusing prefix KV cache. To enable this dual-mode agent without degrading performance, we propose a joint agent-speculator reinforcement learning method, which derives speculation targets from the agent's own rollouts and alternates agent and speculator updates. Across agentic search QA and conversational tool-use agentic tasks, our method improves average next tool-call Hit@1 from 44.1 to 61.2 for Qwen3-4B and from 48.9 to 66.3 for Qwen3.5-4B, while preserving agent task success.

*   **核心问题**：工具调用推测（Tool-call speculation）是一种通过提前预测并预执行智能体的下一次工具调用来隐藏延迟的技术。然而，现有方法存在**推测器-智能体差距（speculator-agent gap）**：用于推测的模型（如更小的LLM或缓存历史）与部署的智能体行为不一致，预测准确率低，且引入额外模型重量与KV缓存的系统开销。
*   **整体含义**：本文提出**自推测智能体**，将智能体与推测器统一为同一个模型，使其在完成任务的同时，能预测自己下一步的工具调用，从而以极简的设计消除推测差距，同时降低延迟和资源开销。

### 2. 论文提出的方法论
*   **核心思想**：单一的LLM \(\pi_\theta\) 同时工作在**智能体模式**和**推测器模式**下。两种模式共享前缀KV缓存，推测器模式通过添加一个固定的推测后缀来触发，直接从部分轨迹预测下一次工具调用。
*   **关键技术细节**：
    *   **奖励构造**：定义智能体任务奖励 \(R_{\text{ag}}\) 为答案准确性；推测奖励 \(R_{\text{sp}} = R_{\text{name}} \cdot R_{\text{args}}\)，其中工具名称匹配得 \(R_{\text{name}}\)（0或1），名称匹配后对参数字典计算宏平均词元F1值 \(R_{\text{args}}\)。
    *   **联合智能体-推测器强化学习（RL）**：
        *   *数据生成*：每个RL迭代步从当前策略采样一组智能体轨迹，并从中自动提取推测对（轨迹前缀 \(h_t\) → 智能体实际下一次调用 \(a_t\)）。
        *   *模式交替训练*：采用固定的更新调度 \(m(k)\) 在智能体更新（优化 \(R_{\text{ag}}\)）和推测器更新（优化 \(R_{\text{sp}}\)）之间切换。典型的调度为4:8（4次智能体更新后接8次推测器更新），两者都使用DAPO策略优化。
    *   **训练稳定化**：
        1.  **SFT预热**：在RL前用成功轨迹和对应的推测示例做监督微调，确保模型能正确输出格式。
        2.  **优化器重置**：在模式切换时重置优化器状态（如Adam的动量），避免来自先前模式目标的干扰。
        3.  **智能体惩罚项**：对无意义重复的工具调用施以奖励惩罚，防止模式坍塌。

*   **实验模型规模单一**：实验仅在4B参数级别的模型上进行。方法在大模型（如70B+）或与推理缩放（reasoning scaling）结合时的效果和动态未知。
