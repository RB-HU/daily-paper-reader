## 摘要
智能体技能为冻结的大型语言模型（LLM）智能体提供可重用的程序化指导，近期工作表明此类技能可通过真实（GT）反馈进行优化。然而，许多应用缺乏真实标签、任务分数、奖励或可靠的任务特定评估器。为此，我们引入自我监督的技能优化（SSO），这是一个仅从无标签任务实例中学习可重用技能的比较框架。在每一步，SSO在当前技能在一个无标签批次上运行，利用部分执行结果生成完整的技能探针，并在同一批次上运行这些探针。LLM裁判比较产生的答案、轨迹、产物或终止状态。一个独立的行为提取器在不知晓裁判决定的情况下识别行为差异。SSO利用这些决定跨实例聚合支持和反对所观察行为的证据。然后，它按所得证据对行为进行排序，并从排名最高的行为中生成新的完整技能。只有当新技能在无标签验证集上优于当前技能时，才接受更新。SSO在封闭式和开放式任务上均超越了现有的无真实反馈提示优化器。在封闭式基准测试中，它接近甚至有时超过了最强的基于真实反馈的技能优化器，而无需使用任何真实反馈。

## Abstract
Agent skills provide frozen large language model (LLM) agents with reusable procedural guidance, and recent work shows that such skills can be optimized with ground-truth (GT) feedback. Many applications, however, lack GT labels, task scores, rewards, or reliable task-specific evaluators. We therefore introduce Self-Supervised Skill Optimization (SSO), a comparative framework that learns a reusable skill from unlabeled task instances alone. At each step, SSO runs the current skill on an unlabeled batch, uses a subset of the resulting executions to generate complete skill probes, and runs the probes on the same batch. An LLM judge compares the resulting answers, trajectories, artifacts, or terminal states. A separate behavior extractor identifies behavioral differences without seeing the judge's decisions. SSO uses these decisions to aggregate evidence for and against the observed behaviors across instances. It then ranks the behaviors by the resulting evidence and renders a new complete skill from the highest-ranked behaviors. The update is accepted only if the new skill outperforms the current one on an unlabeled validation set. SSO outperforms existing GT-free prompt optimizers on both closed-ended and open-ended tasks. On closed-ended benchmarks, it approaches and sometimes exceeds the strongest GT-based skill optimizer without using any GT feedback.

## 2. 方法论
SSO 是一个比较式的优化循环，核心思想是**在行为层面聚合跨探针与任务的比较证据来生成新技能**，而非简单选择最优探针。关键步骤如下：

- **探针生成与锚定比较**：
  - 当前技能 $S_t$ 在无标签训练批次上执行，得到锚定执行结果。
  - 基于当前技能和执行历史，用LLM探针生成器生成 $K$ 个完整的技能探针 $\{P_k\}$。
  - 在同一批次上运行每个探针，得到对应执行结果 $r_k$。
  - LLM裁判对每一对(探针执行, 锚定执行)进行偏好比较，输出标签 $y_{ki} \in \{-1,0,+1\}$，并做位置随机化以减少偏差。

- **行为提取与聚类**：
  - 一个独立的行为提取器接收任务、锚定执行及所有探针执行，输出一组行为描述及其在各执行中的激活状态（存在/不存在/不清楚）。
  - 行为提取器不接触裁判决定，保证描述的独立性和无偏性。
  - LLM聚类器对行为描述进行语义聚类，合并等价行为。

- **证据聚合与排序**：
  - 对于每个有清晰行为变化的比较，计算行为激活差值 $d_{kic} \in \{-1,+1\}$。
  - 证据分配公式：$e_{kic} = \frac{y_{ki} d_{kic}}{|A_{ki}|}$，其中 $A_{ki}$ 是变化的簇集合。此归一化确保每次比较总影响力相等。
  - 累积每个簇的得分 $Q_c = \sum e_{kic}$ 和总证据量 $E_c$。
  - 按 $|Q_c|$ 降序排序，用 $E_c$ 及涉及任务数打破平局，选前 $U$ 个行为簇作为更新单元。

- **技能生成与无标签验证**：
  - 渲染器根据当前技能和选定的行为单元（鼓励/抑制）生成候选技能 $\tilde{S}_{t+1}$。
  - 在无标签验证集上，用同一LLM裁判比较候选技能与当前技能的执行，统计胜/负次数。候选赢得多则更新，否则保持原技能。

## 7. 优点
- **新颖的GT-free技能优化范式**，摆脱了对人工标签或任务评估器的依赖，扩大了技能优化的适用范围。

- **独立的行为提取与无偏比较**：行为提取器与裁判决策解耦，避免结果偏向，保证行为描述的客观性。
- **严谨的验证机制**：通过无标签验证集上的成对比较决定是否接受更新，避免训练过拟合和性能退化。
- **全面的实验验证**：覆盖多模型、多领域、开放式任务，对比GT-based和GT-free baselines，并提供了丰富的消融分析和动态分析。

## 8. 不足与局限
- **计算成本未披露**：优化过程频繁调用大型LLM（裁判、生成、提取、聚类、渲染），AP费用和延迟可能较高，文中缺乏量化讨论。
- **LLM裁判的偏差风险**：虽采用位置随机化和成对比较，但裁判本身可能存在系统性偏好（如长度、风格），影响证据质量，对开放式任务的影响尤其需注意。
- **受限于LLM生成质量**：探针生成、行为描述、聚类和渲染都依赖语言模型，若底层LLM能力不足，可能产生劣质探针或错误行为描述，影响优化效果。
- **技能形式固定**：技能文档为自然语言，无法编码更复杂的结构化约束或策略，可能限制在需要精确逻辑的任务上的潜力。
