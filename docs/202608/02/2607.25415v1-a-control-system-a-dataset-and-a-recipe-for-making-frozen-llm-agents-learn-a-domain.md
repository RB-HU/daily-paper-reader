## 摘要
生产环境中的大语言模型代理越来越多地由一个冻结模型包裹在一个控制套件中组装而成：这个套件包括提示模板、工具集、记忆/检索层、规划策略和验证策略。2026年的两个系统，Meta-Harness（Lee 等人，2026）和 HyperAgents（Meta AI，2026），展示了这个套件本身可以被优化甚至由代理提议者自我重写——代价是要么是昂贵的代码搜索循环，要么是未加约束的自我修改代码，这两者要么无法审计，要么无法与完全黑箱的模型 API 一起使用。我们采取一种更窄、更受限的立场：将套件视为一个小型、固定、人类可读的动作空间，并用经典的样本高效强化学习（ε-贪心上下文赌博机和 REINFORCE）在线学习其策略，根据多目标奖励（任务成功、验证器评分、策略合规性、成本、延迟和未经证实的声明惩罚）进行评分。我们使用 DSPy（Khattab 等人，2024）作为上下文组装器和最强的非自适应基线（DSPy BootstrapFewShot 静态提示）的来源，实例化了这个控制系统，并在三个可验证的任务领域（工具使用工作流、代码生成 HumanEval 和多跳检索问答 HotpotQA）和两个模型提供者（本地 Ollama 模型和 AWS Bedrock）上进行了评估。我们发布了套件控制系统代码、跨领域可验证任务套件、训练过程中的完整轨迹/奖励分解日志，以及一个与提供者无关的部署配方，用于将其应用于新组织的领域和验证设置。

## Abstract
Production LLM agents are increasingly assembled from a frozen model wrapped in a harness: a prompt template, a tool set, a memory/retrieval layer, a planning strategy, and a verification policy. Two 2026 systems, Meta-Harness (Lee et al., 2026) and HyperAgents (Meta AI, 2026), show that this harness can itself be optimized or even self-rewritten by an agentic proposer -- at the cost of either an expensive code-search loop or unconstrained self-modifying code, neither of which is auditable or usable with a fully black-box model API. We take a narrower, more constrained position: treat the harness as a small, fixed, human-legible action space and learn a policy over it online with classic sample-efficient reinforcement learning (an $ε$-greedy contextual bandit and REINFORCE), scored against a multi-objective reward (task success, verifier score, policy compliance, cost, latency, and an unsupported-claim penalty). We instantiate this control system with DSPy (Khattab et al., 2024) as both the context assembler and the source of the strongest non-adaptive baseline (a DSPy BootstrapFewShot static prompt), and evaluate it across three verifiable task domains -- tool-use workflows, code generation (HumanEval), and multi-hop retrieval QA (HotpotQA) -- and two model providers (a local Ollama model and AWS Bedrock). We release the harness-control-system code, the cross-domain verifiable task suite, the full trajectory/reward-decomposition logs from training, and a provider-agnostic deployment recipe for applying this to a new organization's domain and verification setup.

- **核心问题**：生产环境中的大型语言模型代理往往依赖于一整套外围组件（提示模板、工具、记忆、规划、验证等），这个组件构成了一个“套件（harness）”。现有前沿工作（如 Meta-Harness、HyperAgents）试图通过复杂且昂贵的代码搜索或自修改代码来优化此套件，但这些方法存在成本高、难以审计、且无法兼容纯黑盒模型 API 的问题。
- **研究动机**：探索一种更受约束、更可控的替代方案：将套件视为一个固定、小规模、人类可读的动作空间，并使用经典的样本高效强化学习算法在线学习策略。目标是使控制系统既具备多目标优化能力（成功率、验证、合规、成本、延迟），又保持完全的可审计性和黑盒兼容性。

### 2. 论文提出的方法论

- **动作空间定义**：将套件分解为六个离散杠杆：
    - 提示风格（`direct`, `structured`, `reflective`）
    - 工具/检索策略（`never`, `when needed`, `always`）
    - 记忆策略（`none`, `similar successes`, `successes and failures`）
    - 规划策略（`none`, `brief plan`, `plan and revise`）

- **奖励设计**：多目标奖励函数 `R = ws*success + wv*verifier score + wc*compliance - wu*unsupported claims - w$*tokens/1000 - wℓ*latency/1000`，各领域的成功标准由确定性验证器定义（单元测试、状态差异或精确匹配）。
- **在线控制器**：
    - **随机**：在 729 种配置上均匀采样，作为性能下界。
    - **ε-贪心上下文赌博机**：使用任务特征向量上的线性价值估计，配合乐观初始化（避免冷启动死锁）和随机平局打破。
    - **REINFORCE**：在 729 个动作上使用 softmax 策略，线性特征对数几率和熵正则化，采用移动平均基线。

### 6. 论文的主要结论与发现
- **主要发现**：在所有领域和模型上，**DSPy-优化的静态基线均匹配或超越在线自适应控制器**，同时消耗的 token 成本通常更低。例如，工具使用领域（Haiku）静态基线以 285 tokens/ep 达到 96% 成功率，而 REINFORCE 需 680 tokens/ep 仅达 62%。
- **原因分析**：这主要源于 **样本效率差距**，并非在线学习本身的缺陷。从均匀先验开始在 729 维空间中冷启动探索极其低效，远不如基于度量的定向搜索（BootstrapFewShot）有效。即使在 300 集后，在线控制器也仅缓慢爬升至一个较低的平台期，无法在实用预算内达到静态基线的高度。
- **实践指导**：该结论为部署提供了明确指引：应在离线使用静态优化器引导（bootstrap）之后部署在线控制器，而不是从零冷启动。这构成了发布配方 `RECIPE.md` 的核心建议。

### 7. 优点
- **方法论可审计**：将复杂的套件优化约束在一组固定、人类可读的离散动作中，任何性能回归可直接归因于某个具体配置的变动。
- **黑盒兼容**：无需模型或运行时环境具备自我代码修改能力，适用于任何标准对话补全 API。
- **实用多目标**：奖励函数整合了任务成功、验证器信号、策略合规性、成本与延迟，贴近真实部署需求。
- **诚实的负结果分析**：不回避实验结果未达预期，深入剖析样本效率瓶颈，并提炼出对工程师更务实的操作指南，具有极高的实践价值。
- **高质量的发布资产**：完整开源了控制系统代码、数据集、全部轨迹日志和详细的部署配方，复现性和可扩展性极强。
- **工程陷阱的透明记录**：详细记录了冷启动、崩溃隔离和成本计量三个常见工程陷阱及其解决方案，对社区有直接参考意义。

### 8. 不足与局限
- **实验规模与泛化性受限**：实验种子数少（1-3 个），在线学习的 episode 预算远不足以探索 729 维的动作空间，热启动对比缺失。结论的有效性被框定在“小预算冷启动”条件下。
- **评估环境存在合成元素**：工具使用领域是模拟的 CRM 后端，非真实业务系统，其结论向真实复杂环境迁移时可能打折扣。
- **安全度量的简化**：对“未经证实的声明”的度量是在检索领域使用的词汇重叠启发式方法，并非能泛化到开放领域的通用幻觉检测器。
- **提供者覆盖缺口**：因 API 密钥问题未能包含 OpenAI 模型，限制了结论在主流商用模型上的直接验证（论文承认此为局限性而非设计缺陷）。
- **成本控制疏漏**：整体实验总花费超过了单任务预算帽的聚合，虽然各分实验未超支，但暴露了跨实验链路上限的缺失。
